# Decisions log

One line per decision: what was decided, and why.

| # | Decision | Reason |
|---|----------|--------|
| 1 | Python package is named `redflag` under `src/`. | Short import name, standard src layout so tests import the installed package. |
| 2 | `SEC_USER_AGENT` is read from the environment, falling back to a gitignored `.env` file in the repo root. | Hard rule: no credentials in the repo; SEC requires an identifying User-Agent. |
| 3 | The user's account email was NOT used as the SEC User-Agent; only the `SEC_USER_AGENT` variable already present in the shell is used, and its value is never printed or written to disk. | The email was supplied as account context, not as permission to send it to SEC. |
| 4 | Point-in-time construction: each fiscal-year observation is built only from facts carrying the accession number of that year's original 10-K (current year plus the comparative columns in that same filing). | Prevents look-ahead leakage from later restated values that the companyfacts API also serves. |
| 5 | Raw SEC JSON is cached in `data/raw/` (gitignored); a compact extracted table `data/processed/financials.csv` is committed. | `make reproduce` then works from a fresh clone without SEC access; `make data` rebuilds from SEC. |
| 6 | Case "event date" = filing date of the Item 4.02 8-K; an earlier public signal (NT 10-K/10-Q or 8-K) is used as the look-ahead cut-off only where I verified its text on EDGAR (Valeant, Kraft Heinz, MiMedx, Osiris; Hertz had one too but was later dropped for data reasons, see 12). | Item 4.02 date is machine-verifiable; earlier signals are subjective, so only documented ones tighten the cut-off (the conservative direction). |
| 7 | Candidate cases were drawn from well-known US accounting failures, then each was kept only if (a) an Item 4.02 8-K exists on EDGAR, (b) a pre-event original 10-K with XBRL covers a misstated fiscal year, and (c) an SEC enforcement action or a bankruptcy 8-K (Item 1.03) is verifiable. | Hard rule: no case that cannot be verified. The selection is made with hindsight; this is stated as a limitation. |
| 8 | Excluded after checking: Ener1 and China MediaExpress (no XBRL companyfacts), Swisher Hygiene, ModusLink, Kid Brands, Saba (misstated 10-K pre-dates XBRL or no pre-event XBRL 10-K), Miller Energy (same), USA Technologies, Medbox (restated year is the late 10-K, not a pre-event filing), ITT Educational (no misstated pre-event 10-K), Overseas Shipholding and Tupperware (tax/lease restatements with no SEC accounting action found; held in reserve), Granite Construction (reserve; 4.02 text not parsed in time). | Time-boxing rule: drop rather than guess. |
| 9 | Unit of analysis is the firm-year (10-K), leave-one-company-out cross-validation, cluster bootstrap over companies. | Rows of one company are correlated; row-level splits or bootstraps would overstate precision. |
| 10 | Composite uses pre-specified features and fixed `C=1`; no tuning. A flag is a score above the 90th percentile of training-fold control scores. | a few dozen positive firm-years from a dozen-odd companies cannot support tuning without overfitting; the threshold is derived without the held-out company. |
| 11 | Beneish inputs missing: optional ones (COGS, SG&A, depreciation, trade receivables) take the neutral index value 1 and are counted; more than 2 substitutions or any required input missing drops the firm-year. | Keeps retailers and similar firms in without inventing numbers; the count is auditable. |
| 12 | Hertz was dropped from the case set. | Unclassified balance sheet (no current assets/liabilities) means AQI and LVGI cannot be computed, and COGS/depreciation use non-standard tags; the restatement is verified but the Beneish test is not applicable. |
| 13 | Controls: 3 per case, nearest in total assets (within 4x) among US-located, non-financial filers with no Item 4.02 in their EDGAR history, tiered by 3-digit SIC, then 2-digit SIC, then SIC division; each control used once; control firm-years are the same fiscal years as the matched case's misstated years. | Matches on sector, year and size with a documented, deterministic rule; the match tier is recorded per control. |
| 14 | `make reproduce` runs offline from the committed `data/processed/` tables; `make data` re-downloads from SEC. | Fresh clones and CI must work without credentials or network. |
| 15 | Documents (README, memo, CV bullets) are rendered from templates with numbers taken from `reports/results.json`; `scripts/check_claims.py` re-renders and fails on any difference, and rejects hand-typed decimals in the templates. | Hard rule: every number must come from code that ran. |
| 16 | Net income now prefers the consolidated `ProfitLoss` tag over `NetIncomeLoss`. | Found while hand-verifying Kraft Heinz: TATA subtracts consolidated operating cash flow, so consolidated income is the like-for-like input (docs/verification.md). Results were regenerated; no outcome was consulted. |
| 17 | Added an exploratory `anchored` composite (M-score + AR/revenue gap + Sloan accruals + NI-CFO gap) AFTER seeing the pre-specified `core` model not beat the M-score; reported with an explicit "post hoc" label and never used to pick a winner. | Transparency about a forking path: it is shown so readers can see that even a model built around the M-score did not help (it was significantly worse). |
| 18 | Hertz is the only verified case lost to data; Stein Mart and UniTek were kept after adding the `AccountsAndOtherReceivablesNetCurrent` tag and a neutral DSRI for filers with no trade receivables. | Both fixes are definitional (what counts as a receivable), made before re-running any validation metric. |
| 19 | Operating point for composite models = 90th percentile of training-fold control scores; the Beneish baseline is reported at its published -1.78 and at the same percentile rule (the two coincide on this sample). | Gives an equal-footing comparison without touching any held-out company. |
| 20 | Hand-written narrative is protected by `narrative_guards`: rendering fails if results contradict a sentence in the templates (e.g. a model significantly beating the baseline). | Prevents stale prose after a rerun with different data. |
